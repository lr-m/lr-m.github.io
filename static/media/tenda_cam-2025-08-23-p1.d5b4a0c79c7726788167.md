# Backstory

At the end of 2023, me and [iMoD](https://imod1998.dev/) were bored and looking for a project to work on. We cam across the Tenda CP3, and both bought one of them each, and then one night we started working on them.

Long story short, by the end of the night we had the camera playing *fart.wav* and MW2 nuke sounds... In other words, this camera was so full of bugs and backdoors it wasn't even fun to do research on, so since then it has been sat in my cupboard.

As time has passed, I have seen other bits of research come out on the camera, and it seemed like a good chunk of the backdoor-esque bugs had been disclosed by other people:
- [Finding (and exploiting) vulnerabilities on IP Cameras: the Tenda CP3 case study](https://arxiv.org/html/2406.15103v2)
- [tenda_cp3_hacking](https://github.com/g1tblame/tenda_cp3_hacking)
- [Security Cameras - A Penetration Tester's Journey](https://tobiabocchi.me/posts/ip-cam-pentester-journey/)

After seeing that other people have looked at the camera, I figured it would be more challenging to hack, so I blew the dust off of the camera and fired it up for the first time in a couple of years. There are definitely some bits in that research that will be useful for enabling further research, such as *telnet* creds.

# Reversing Open Ports

I'll only mention the interesting ones here (at least for the sake of this channel), there are some RTSP ports and other stuff but I won't be looking into those. Previous research has also identified a bunch of these ports, so check those out if you are interested.

## apollo

This is a huge binary that seems to be delivering most of the camera functionality.

![touchdown.png](/assets/images/tenda_cam/p1/touchdown.png)

### 8699

This is a pretty simple interface, very command-line esque with a LOT of handlers available, I am sure lots of bugs will fall out of this. 

Some example inputs that can be sent directly to the port:
- **get_rtsp_url {index}**
- **wifi_connect SSID PWD**
- **!reboot** (yes thats a command injection, more on that later)

### 9876

The format for this is slightly more complicated:
- 0x10 length header:

| Name | Use |
| - | - |
| Unknown 1 | Not used for anything |
| Payload size | The size of the payload |
| JSON size | Size of the JSON string |
| Unknown 2 | Not used for anything |

The protocol sends JSON commands (like **{"cmd": "run_cmd", "run": "command"}**) followed by optional binary data, with the header indicating the JSON size and any offset needed for the operation.

Here is the function to send a command to the port:

```python
def _send_command(self, payload, json_size, offset=0):
    """
    Send command with header and payload to the server
    
    Args:
        payload (bytes): The payload to send
        json_size (int): Size of JSON portion
        offset (int): Offset value for header
        
    Returns:
        bytes: Response payload (without header) or None on error
    """
    if not self._connect():
        return None
    
    try:
        # Construct header: [0, offset, json_size, 0]
        header = struct.pack('<4I', 0, offset, json_size, 0)
        
        info("Sending command:")
        print("Header:")
        hexdump(header)

        print("Payload:")
        hexdump(payload)
        
        # Send header and payload
        self.sock.send(header)
        good("Header sent")
        
        self.sock.send(payload)
        good(f"Payload sent ({len(payload)} bytes)")
        
        # Receive response
        response = self.sock.recv(4096)
        if len(response) < 0x10:
            bad("Response too short")
            return None
        
        info("Received response:")
        info("Header:")
        hexdump(response[:0x10])

        info("Payload:")
        hexdump(response[0x10:])
        
        return response[0x10:]
        
    except socket.error as e:
        bad(f"Socket error: {e}")
        return None
    except Exception as e:
        bad(f"Unexpected error: {e}")
        return None
    finally:
        self._disconnect()
```

## noodles

This is a smaller secondary binary that exposes a bunch of interesting ports - another interesting name.

![noodles.png](/assets/images/tenda_cam/p1/noodles.png)

### 1300

Port 1300 uses a simple XML-based protocol. The communication format consists of:

- Fixed payload size: All payloads must be padded to 0x400 (1024) bytes with null bytes (I think, it wouldn't work without the padding)
- XML command structure: Commands are wrapped in XML tags like **\<UPGRADE\>**, **\<SYSTEM\>**, **\<ELFEXEC\>**
- To interact with the port, send XML payloads directly

Here's the basic function to send commands to this port:

```python
def send_payload(self, payload):
    """Send a padded payload and return response"""
    # Pad payload to standard size
    if len(payload) < self.payload_size:
        payload += b'\x00' * (self.payload_size - len(payload))
    
    info("Sending payload:")
    hexdump(payload)
    
    try:
        with self.connect() as sock:
            bytes_sent = sock.send(payload)
            info(f"Sent {bytes_sent} bytes")
            
            response = sock.recv(4096)
            info(f"Received {len(response)} bytes")
            if response:
                hexdump(response)
            
            return response
    except Exception:
        info("Failed to send payload (or device crashed)")
        return None
```

The port supports various XML commands including system command execution (**\<SYSTEM\>**), file uploads (**\<ELFEXEC\>**), file downloads (**\<DOWNLOAD\>**), and firmware upgrades (**\<UPGRADE\>**). This seems to be a maintenance/debugging functionality that has been left behind.
